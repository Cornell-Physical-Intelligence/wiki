# UI conventions

- Recruitment lives in `lib/recruit/` (five server modules behind one registry: cycles, applications, people, roles, site; `flow.js` is the flow model they share) and `src/client/recruit-*.js` (client modules behind `RECRUIT.register`: core, cycles, flow, stage, people, person, insights). A cycle is a flow of stages; any stage can have a website form and a checklist, and new cycles start from the default flow in `lib/recruit/sections.js` (keys `[a-z][a-z0-9_-]{0,39}`; nothing is hard-wired to a key beyond the defaults and the old `POST /api/interest` bridge); the club website renders whatever forms the cycle has from `GET /api/recruit/site`; flags, comments, checklist values, stage and status belong to the person in a cycle (`recruit_people`), never to a submission; who goes where after a stage is its connections plus its answer-based `split` (`lib/recruit/flow.js`), never code keyed on a subteam or a form; change stages through `lib/recruit/sections.js` and a stage's panel (`src/client/recruit-stage.js`), not by adding modules or growing `lib/interest.js`. See README "Applications (recruitment)".
- The CUPI logo is the four-circle mark in `src/client/logo-row.svg` (row) and `src/client/logo-square.svg` (2x2, icons). Use those files for any logo, favicon, or brand surface; the crab is mascot art only, never the logo. See README "Brand".
- Every dropdown must use a custom HTML/CSS menu. Native `<select>` and `<datalist>` dropdowns, including browser and operating-system option menus, are not allowed. Styling a native select with `appearance: none` does not satisfy this rule; the opened menu must also be custom.
- Reuse the wiki's custom dropdown and menu patterns in `src/client/ui2.js` and `src/client/main.js`. Preserve keyboard navigation, selected-state indicators, Escape/outside-click dismissal, and focus return to the trigger.
- Keep interface copy direct. Do not add subtitles or helper text that restate a heading, placeholder, or nearby control. Explanations should provide information needed to use a feature or understand a result or error.
